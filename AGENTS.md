
- Les inscriptions en libre-service passent uniquement par la fonction `inscription` (Turnstile vérifié côté serveur, inscription directe coupée dans l’authentification) — empêche les robots de créer des comptes via l’API ; le secret TURNSTILE_DESACTIVE=true coupe la vérification sans republier.
- Les demandes de devis ne sont insérées que via `soumettre_demande_devis` ; un trigger BEFORE INSERT calcule `moderation`, et les emails prestataire/admin partent depuis la base (trigger + rattrapage dans la tâche nocturne des scores) avec réservation atomique de la date d'envoi — évite les envois non modérés, les doublons et les pertes d'email.
- Tout ce que voit ou compte un prestataire (accès, tableaux de bord, taux de réponse, score, compteurs) se limite aux demandes `moderation = 'valide'` — une demande suspecte ne doit jamais l'atteindre ni le pénaliser.
- La date d'une demande s'affiche partout via `formaterDateEvenement` (src/lib/dateDemande.ts, copie identique dans supabase/functions/_shared/date-demande.ts, vérifiée par un test) avec `date_precision` jour/mois — un mois seul ne doit jamais apparaître comme une date précise.
- Prerender: `signature_visible` = md5(data hash + `prerender_snapshot_version()`); bump that SQL version on any global component change. A page is re-rendered only when `signature_visible` ≠ `signature_rendue`; the nightly chain (`cron-prerender-nightly`, hops chained via `EdgeRuntime.waitUntil`, sequential, stops at empty queue / 05:30 UTC / MAX_HOPS, KPI export on the first hop only) also refreshes the socle every night plus at most 100 snapshots older than 30 days — no blind age-based refresh, Browserless stays at 1 GB.
- Dans `ai-playground`, aucun paramètre `temperature` n'est envoyé au provider anthropic (le modèle le refuse) ; il reste envoyé à Mistral, et la ligne `ia_tests` d'un appel Anthropic garde `temperature` NULL — évite l'erreur « temperature is deprecated for this model » et n'enregistre pas une valeur qui n'a pas été appliquée.
- tags_ia : le vocabulaire envoyé à Claude = liste d'ambiances fixe + « Éco-responsable » + options des champs `champs_categories.usage_ia = true` (communs, mère, fille de la fiche) ; filtrage exact côté code et 12 étiquettes max — empêche les étiquettes pratiques (paiement, délais) ou hors catégorie.
- Les Edge Functions IA ne codent aucun nom de modèle : elles lisent les secrets AI_MODEL_LIGHT, AI_MODEL_RICH et EMBEDDING_MODEL et refusent de tourner s'ils manquent — changer de modèle sans redéployer et éviter d'appeler un modèle non tarifé. `traiter-file-embeddings` garde un rythme lent (lots de 25, pause entre fiches) pour rester sous la limite de débit Mistral.
- Tout appel IA côté couple passe par la fonction `ai-gateway` (prompt actif en base, quota réservé atomiquement par `reserver_quota_ia` et annulé en cas d'échec, refus si tarif manquant, fournisseur déduit du préfixe claude-/mistral-, sinon erreur) — coûts, quotas et budget restent contrôlés côté serveur.
- Atelier IA – assistant : la recherche passe par `rechercher_prestataires` (service_role seul, pertinence (similarité + bonus sous-catégorie + bonus étiquettes trouvées dans l'intention, plafonné, réglages dans ia_reglages) normalisée min-max sur le top 30 puis pondérée avec score_classement ; fiches allégées pour Claude (zone courte, champs usage_ia + infos pratiques, fiche déjà fournie dans le message non renvoyée), complément hors zone même région d'abord) ; le résultat envoyé à Claude est purgé des champs de classement et toute recommandation absente des résultats du message est supprimée (`id_invente`) ; les messages ne sont écrits que par `ai-gateway` et les copies des retours par trigger — l'IA ne peut citer que des fiches réellement trouvées et le couple ne peut pas forger l'historique.
- Notre style : tout fichier du bucket privé maries-assets passe par la fonction `upload-asset` (type réel par signature, HEIC refusé, SVG nettoyés, métadonnées retirées, 10 Mo/50 Mo, écriture service_role) ; le couple n'a que SELECT/DELETE ; `analyse_ia` n'est écrit que par ai-gateway ; `logo_perso_url` est un chemin affiché par URL signée — aucun envoi direct ni URL publique.
- Monogrammes : lettres converties en tracés avec opentype.js depuis les TTF OFL du bucket public `polices` (opentype.js ne lit pas le WOFF2 de Google Fonts) ; l'aperçu est le SVG exporté, qui ne dépend d'aucune police installée.
- Planning de l'Atelier : les tâches issues de `modeles_retroplanning` ne sont créées, recalculées ou masquées que par `synchroniser_taches_couple` (déclencheurs sur profils_mariage et modeles_retroplanning) ; le couple ne coche/masque/re-date que, et seules les tâches perso lui sont insérables/supprimables — l'échéance (`echeance_retroplanning`) a une copie JS dans src/lib/planning.ts vérifiée par un test.
- Seule la fonction `inscription` passe `origine: 'auto_inscription'` dans user_metadata ; `handle_new_user` écrit `auto_inscription` uniquement pour cette valeur, sinon `inscription_admin` (aucune action requise pour les créations côté équipe) — app_metadata n'est pas encore présent quand le trigger s'exécute.
- Les robots reçoivent le pré-rendu via middleware.ts, qui récupère prerender-serve et rétablit Content-Type text/html (sans la CSP sandbox) : la passerelle des fonctions force text/plain + CSP sandbox sur tout HTML en GET, et un rewrite Vercel les transmet tels quels — Google ne verrait qu'un fichier texte. Les rewrites prerender-serve de vercel.json ne sont plus qu'un filet.
- Prerender snapshots embed local bundle CSS with absolute resource URLs at capture; serving repairs legacy missing main CSS using the current published shell, or falls back to the application on failure — hashed deployment assets must not leave stored pages unstyled.
- Prerender queue priority is computed only by the `trg_prerender_priorite` trigger whenever a row is `a_traiter`: no snapshot +1000, then home 900 > categories 800 > regions 700 > articles/pages 600 > 'correct' fiches (≥3 photos, ≥300-char description) 200+score > other fiches 100+score; ≥2000 (manual single-page recapture) is kept; the same trigger requeues an `a_jour` row whose `signature_visible` changes away from `signature_rendue`, and publishing a fiche inserts it via `trg_prerender_fiche_publiee` — callers never set the level themselves.
- KPI quotidiens : `get_kpi_quotidiens(date, inclure_photo)` (service_role seul) + `kpi-export-sheets` (compte de service, onglet `kpi_quotidiens`, date en colonne A, ligne remplacée si présente, indisponible = cellule vide) appelé une fois par nuit dans le `finally` isolé du premier appel de `cron-prerender-nightly` ; une seule ligne (la veille, heure de Paris) qui porte aussi l'état « photo » ; fiches de test dans `kpi_fiches_test` + comptes @lesnoces.test exclus — aucun nouveau cron, une erreur d'export n'affecte jamais le pré-rendu.
- Source des conversions : `src/lib/sourceVisite.ts` garde le premier contact de la session (utm, domaine du referrer, `gclid_present` booléen jamais la valeur ; copie localStorage 30 min pour les nouveaux onglets, aucun cookie) et l'envoie en `p_source` à `soumettre_demande_devis` / `obtenir_telephone_prestataire` ; `classer_source_conversion` fixe `source_groupe` par trigger : payant = gclid ou utm_medium ∈ (cpc, ppc, paid, paid_social, display), fbclid jamais pris en compte ; ordre google_ads → chatgpt_ads/organique (utm_source=chatgpt.com sans medium payant = organique) → meta_ads/organique → pinterest_ads/organique → email → seo (moteur sans payant) → direct → autre.
- `nombre_demandes` = demandes `moderation = 'valide'`, maintenu par le trigger `trg_nombre_demandes` ; il n'est pas exposé dans `prestataires_public` (admin et propriétaire seulement).
- Prerender: one DB lock (`prerender_verrou_*`) per render chain, beaten each batch (active <5 min, expires 10 min); busy lock → nightly still reconciles + KPI, stops `chaine_deja_active`; back-office uses it too — no concurrent renders.
